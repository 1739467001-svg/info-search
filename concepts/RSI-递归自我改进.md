# 💡 RSI（递归自我改进 / Recursive Self-Improvement）

> 整理日期：2026-09-28 ｜ 类型：概念解读 ｜ 版本：**v2 深度版** ｜ 置信度：**高**（6 个来源实际抓取核实）｜ 关联：`relations.md`
> 一句话总结：**AI 系统把"改进自己"当作任务，改进出的更强版本继续改进自己，循环复利。2022–2025 年，这条路线从理论（Gödel 机）走到工程现实：AlphaTensor 破矩阵乘法纪录 → FunSearch/AlphaEvolve 用"LLM+自动评估器"进化程序 → DGM 直接改自己的代码 → SEAL 直接改自己的权重。**

---

## 1. 名词解释（准确版）

**定义：** Recursive Self-Improvement（RSI）指 AI 系统以"自身"为改进对象——修改自己的代码、训练流程或权重——并用改进后的版本进行下一轮改进，形成正反馈循环。

**思想源头：** 统计学家 I. J. Good 1965 年提出"超智能机器"（ultraintelligent machine）思想实验：能设计更好机器的机器将引发循环改进，即"智能爆炸"（intelligence explosion）。⚠️（经典论述，本轮未能在线核验原文。）

**排歧义（两个常见误会）：**
- 股市 RSI = Relative Strength Index（相对强弱指标），无关；
- "自我改进"在 2025 年语境下分**三个深度层级**（很多人混为一谈）：
  ① **间接递归**：改进"制造自己的工厂"（AlphaEvolve 优化训练流水线/算力调度）；
  ② **改自己的代码**：agent 重写自己的 harness/工具（Darwin Gödel Machine）；
  ③ **改自己的权重**：模型生成数据/自编辑再训练自己（STaR、SEAL）。
  当前（2026 年）三者全部真实存在，但都在受限环境中运行，没有一个是"自主失控"的。

## 2. 机制详解（四个代表系统的内部构造）

### 2.1 理论原型：Gödel Machine（Schmidhuber, 2003 ✅ arXiv:cs/0309048）

论文全名《Goedel Machines: Self-Referential Universal Problem Solvers Making Provably Optimal Self-Improvements》。机制：
1. 初始代码里含一个**证明搜索器**（proof searcher），公理描述硬件、自身代码和效用函数；
2. 搜索器系统地测试"证明技术"——即输出为证明的程序；
3. 一旦**证明**某个自我改写会提升期望效用，就执行改写（包括改掉证明搜索器本身）；
4. 由于每次改写都有最优性证明，理论上不会陷入局部最优。

**它是"RSI 的数学上限"**——至今无人完整实现，后续所有实际系统（DGM 等）都放弃了"证明"要求，改为"实证验证"。

### 2.2 间接递归：AlphaEvolve（DeepMind, 2025.5 ✅官方博客）

进化式编码 agent，一次迭代循环：
1. **Prompt sampler** 从程序数据库中挑选有希望的父代程序 + 启发信息，拼装提示词；
2. **Gemini Flash**（广度：产生多样候选）与 **Gemini Pro**（深度：精修代码）生成程序变异；
3. **自动评估器**（automated evaluators）验证并打分——这是方向舵，评估错则进化错；
4. **程序数据库**（进化存档）保存最优个体，供下一轮采样（官方介绍其可进化整个代码库，而非 FunSearch 的单个函数）。

它没有改自己的权重，但它优化的对象包括**训练 Gemini（自己的底座）的流水线**——间接递归。

### 2.3 改自己的代码：Darwin Gödel Machine（2025 ✅ arXiv:2505.22954）

机制：维护一个**agent 档案库**（archive）——
1. 从档案采样一个 agent；
2. 基础模型（LLM）对其代码生成变异；
3. 在编码基准上**实证验证**（不要求证明，区别于理论 Gödel 机）；
4. 达标的变体入档，档案长成一棵不断分叉的"agent 进化树"（开放式探索）。

战绩：**SWE-bench 20.0% → 50.0%**；Polyglot 14.2% → 30.7%。安全措施：沙箱隔离 + 人类监督。

### 2.4 改自己的权重：STaR（2022 ✅）与 SEAL（MIT, 2025 ✅）

- **STaR**（arXiv:2203.14465，Zelikman/Wu/Mu/Goodman）：自举推理——模型给自己生成的推理路径打分，只保留"推理正确"的样本微调自己，循环往复。关键技巧"rationalization"：答错时把正确答案喂回去让它生成能到达答案的推理。战绩：在 CommonsenseQA 上**追平了比它大 30 倍的模型**。
- **SEAL**（arXiv:2506.10943，MIT，Zweiger 等）：模型生成"**自编辑**"（self-edit）——重组信息、设定优化超参、调用工具做数据增强——然后用 SFT 把自编辑**固化进权重**；再外层用 RL 训练"怎么产生好的自编辑"，**奖励信号 = 更新后模型的下游表现**。这是"模型自己决定自己怎么被训练"的最早完整框架之一。

## 3. 实例演算（走一遍 AlphaEvolve 的循环）

以官方博客核实的"Gemini 矩阵乘内核提速 23%"为例，一轮循环长这样：

```
① 数据库存有 [当前内核代码 + 历史最优版本 + 各自跑分]
② Prompt sampler 挑出Top-K 内核 + 「改进方向」提示（如减少内存搬运）
③ Gemini Flash 生成 ~N 个粗变异（换算法、换tiling、换指令顺序）
④ Gemini Pro 对最有希望的 1-2 个做深度重写
⑤ 自动评估器逐个跑真实 benchmark：提速 23% 的胜出，其余淘汰
⑥ 胜者写入数据库 → 成为下一轮的父代
   （千轮循环后 → 该内核使 Gemini 训练时间 -1%）
```

要点：**LLM 只负责"变异"，评估器负责"选择"**——进化论式分工。这也是为什么评估器质量是整个系统的天花板（呼应库内 EVAL / Goodhart 条目）。

## 6. 争议与视角

| 视角 | 观点 |
|------|------|
| 快速起飞派 | RSI 越过阈值后能力指数脱缰（Good 的智能爆炸；Yudkowsky"FOOM"论） |
| 渐进派（Hanson 等） | 回报递减+工程瓶颈，改进是连续渐进的（2008 年 FOOM 辩论未决） |
| 工程现实派 | 2025 年的"递归"全部受评估器质量、算力、沙箱约束；与"自主失控"距离很远 |
| 对 AlphaEvolve 的具体质疑 | ① 评估器只覆盖可自动打分的任务，泛化性存疑；② "优化自家工厂"与"自我改进"之间隔着一层，宣传话术成分需打折；③ 成果依赖 Google 级算力，普通人无法复现 ⚠️（此三条为综合社区讨论的一般性观点，本轮未逐条核验具体出处） |
| 安全治理 | 主流前沿安全框架将"自我改进/失控"列为关注能力；DGM 论文明确采用沙箱+人工监督作为先决条件 ✅ |

## 7. 如何理解与动手（给 AI 开发者）

**认知锚点：** 把 RSI 理解为"**进化算法 + LLM 当变异算子 + 评估器当适应度函数**"的现代组合——进化计算是 60 年的老技术，新意在于 LLM 让变异有了"语义智能"。

**微缩实验（一个周末可完成）：**
1. 选一个可自动打分的任务（如：让某 prompt 的输出通过 N 条断言）；
2. 写死评估器（断言通过率）；
3. 让 LLM 重写 prompt（变异），保留 Top-K（选择）；
4. 循环 20 代，画适应度曲线；
5. 观察曲线什么时候停涨——那就是你这个任务上的"评估器天花板"。

这个闭环就是 AlphaEvolve 的微缩版，能亲手体会"评估器=进化方向"的含义。
